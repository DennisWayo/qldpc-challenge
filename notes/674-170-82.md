# [[674,170,82]] - cyclic-ideal generalized-bicycle code

Distance is a witness-backed upper bound (`d <= 82`), not an exact-distance
claim.

## Direction & hypothesis

This entry targets the unrestricted / weight-9plus board. At search time the
score to beat was `1573.977` from `[[682,172,79]]`, so a lift near 700 with
rate near one quarter needed distance at least 79. Prime lift `m = 337` is a
useful grid point because degree-85 cyclic ideals give `k = 170` exactly for a
two-block generalized-bicycle CSS code of length `n = 674`.

The search hypothesis was that divisor-constrained sparse circulants at this
rate could still use more of the allowed check-weight budget than earlier
lighter runs. This candidate has maximum check weight 26.

## What was searched

The search swept cyclic generalized-bicycle candidates over
`m = 333,337,339,343,345,347,349`. For each odd lift it factored `x^m + 1`
over GF(2), selected divisor ideals with degrees in the 75 to 96 range, mined
sparse words of weight 12 through 16 in each ideal, and paired them with up to
4 relative shifts.

Pairs were kept only when the polynomial gcd gave exact designed dimension
`k >= 150`, the max row weight was at most 32, and a first randomized
information-set screen found a nontrivial logical witness. The submitted
candidate came from the `m = 337` part of the run.

## Evidence trail

The submitted file is `codes/674-170-82.json`. It has `n = 674`, `k = 170`,
maximum check weight `w = 26`, and witness-backed upper-bound distance
`d <= 82`, with side witnesses included in the JSON.

The confirmation ladder for this candidate was:

- Initial packaged candidate: `[[674,170,86]]`, score `1865.460`.
- Deeper side-specific fast witness search: 20000 trials per side, pair depth
  24, 8 threads, found `d_X <= 86` and `d_Z <= 86`.
- Trusted candidate gate: `verify/validate_candidate.py` passed with no
  structural failures, no exact duplicate, no WL-equivalent board warning, and
  no lighter logical found in the verifier refutation pass of 8000 RIS trials
  with seed `37260917`.
- Follow-up optimized RIS pressure: 50000 trials found a validated X logical
  of weight 83, and 250000 trials found the submitted validated X logical of
  weight 82. This refuted the earlier `d <= 86` claim.
- Extra SAT refutation pressure at the earlier `W = 85` setting timed out
  rather than proving exactness. This is not an exact certificate.

The final score is `170 * 82^2 / 674 = 1695.964`.

## Dead ends

The highest packaged score from this run was `[[690,168,90]]`, but an
exact-distance follow-up using the SAT certifier found much lighter logicals
and refuted that claim. Several other `m = 345` candidates similarly collapsed
under SAT descent, often on the X side. The initial `[[674,170,86]]` claim was
also too high: optimized RIS later found the submitted weight-82 X logical. The
result still clears the target score while using a witness actually found by
the stronger refutation path.

The `m = 347` and `m = 349` sweeps selected no divisors in the requested degree
band. Some early `m = 333` divisors produced no sparse words at the configured
word-weight range.

## Tools

The search used the repository verifier stack, `verify/gf2_fast.cpp` for fast
GF(2) randomized witness search, `verify/validate_candidate.py` for the trusted
local gate, and `verify/sat_certify.py` for the follow-up SAT refutation
attempt.

## Reproduction

Let `A` and `B` be length-337 binary circulants over `Z_337`. Use first-row
supports:

`a = [0, 1, 22, 53, 61, 66, 79, 81, 140, 150, 162, 185, 201, 204]`

`b = [44, 48, 74, 112, 212, 245, 246, 282, 293, 298, 306, 314]`

Then build the CSS checks as `H_X = [circ(a) | circ(b)]` and
`H_Z = [circ(b)^T | circ(a)^T]`. The complete parity-check supports and
distance witnesses are recorded in `codes/674-170-82.json`.
